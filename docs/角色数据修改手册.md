# 角色数据修改手册（SOP）

> **适用范围**：改 `src/data.js` 里 `RAW_CHARS` 的**角色配装数据**（套装 / 主词条 / 追加属性 / 语义规则）。
> 字段格式与枚举取值见 [`AGENTS.md`](../AGENTS.md) §3，本文只讲**判定与流程**。
> 批量重建走 `tools/rebuild_data.py`（见 [`AGENTS.md`](../AGENTS.md) §5），本文是**单条 / 少量手改**的路径。

---

## 0. 三条不变式（改之前先记住）

1. **第 0 组是主推**，其余是备选。角色卡片展示的永远是第 0 组（`charCardHtml` 里 `viewIdx = max(0, findIndex(priority==='main'))`）。
2. **`subs` 的数组顺序就是展示顺序**，是唯一顺序来源。想让「暴击伤害排在暴击率前面」，就是把 `subs` 里的 `cd` 挪到 `cr` 前面——没有别的开关。
3. **凡是人工判断出来的语义，必须 `source:'manual'`**。这是数据能不能活过下次重建的唯一保险丝。

## 1. 第一步：你到底要改哪一种

| 诉求 | 改哪里 | 必须标 `manual`？ |
|---|---|---|
| 调整追加属性**先后顺序** | `subs` 数组顺序 | ❗是（顺序是人工校准的结果） |
| **新增 / 删除**一个追加属性 | `subs` 数组 | ❗是（wiki 表里没有的词条尤其） |
| 标「两条同等优先」 | `subRules.equal: [[a, b]]` | 视来源，见 §3 |
| 标「★必需」 | `subRules.required: [...]` | 视来源，见 §3 |
| 标「◇条件需要 + 理由」 | `subRules.optional: [[id, '理由']]` | ❗**永远**是 manual |
| 改主词条（沙 / 杯 / 冠） | `sands` / `goblet` / `circlet` | 不需要（不进 subRules） |
| 换套装 | `sets` | 不需要 |
| 改「配装功能定位」 | **别改** `roles` | —— 已改为由所选套装的 2/4 件套效果**实时派生**，定位在「圣遗物套装管理」维护（`AGENTS.md` §4.6） |

⚠️ **只改 `subs` 不够**：如果原来有 `equal: [['cr','cd']]` 而你要的是「cd 严格优先于 cr」，**必须同时删掉这一对 `equal`**。否则展示顺序虽然变了，权重语义仍是「同权」，方案页与合并逻辑不会跟着变。

## 2. `subRules` 语义速查

```js
subRules: {
  required: ['cr'],                              // ★ 必需
  equal:    [['cr','cd']],                       // ＝ 与上一条同权
  optional: [['er','需少量，用于优化大招循环']],   // ◇ 条件需要（成对写法，理由不能丢）
  source:   'manual',                            // 人工校准 / heuristic 可重算
}
```

| 字段 | 页面渲染 | 语义 |
|---|---|---|
| `required` | ★ | 必需。取并集后按「人数 → 名次」截断并置池首，上限 `SUB_REQ_MAX = 4`；权重 ×1.25 |
| `equal` | ＝ | 与上一条**同权**（不衰减）。数组内是成对写法 `[a, b]`，可多对 |
| `optional` | ◇ | 条件需要。**不进入**自动合并的高优先集合。写法 `[[id, '理由']]`；理由统一「需要」式短句——「携带<武器>时需要」「<玩法>需要」「<命座>后需要」「需少量，<用途>」 |
| `source` | —— | `manual` 人工维护 / `heuristic` 由定位推导、可重算 |

## 3. 什么时候必须写 `source:'manual'`（硬判据）

**机制**：`tools/apply_wiki_builds.py` 的 `existing_subrules()`（约 218 行）**只保护 `source == 'manual'` 的组**。重建内置数据时，heuristic 组的 `subRules` 会被重新计算的规则**整个覆盖**。

满足**任一**条件就写 `manual`：

1. 词条 / 顺序来自**攻略图或人工判断**，观测枢 wiki 结构化表格里没有；
2. 顺序是**人工校准**的（不是 wiki 原始顺序）；
3. 带 `optional` 理由（理由一旦丢失无法复原）；
4. 任何你不想被下次重建抹平的东西。

`heuristic` 只留给：**由配装定位自动推导、丢了可以重算**的规则。

判断某个 note / 理由会不会丢，就看它所在组的 `source` 是不是 `manual`。

## 4. 版本号与 CHANGELOG —— **必须手改**

> ⚠️ **纠正一条过期说法**：`build.js` **只校验，不改写**。它做两件事——
> ① `APP_VERSION` 与 `CHANGELOG[0].v` 字符串不等 → **直接抛错**；
> ② 源码日期 ≠ `git log -1 --format=%cs` → 只 `console.warn('版本日期待提交校验…（保留源码日期）')`，**源码一字不动**。
>
> 所以「日期不用管、build 会填」是错的。**不改就不会变版本，更新公告也不会弹。**

规则：

- 新的一天发布 → `APP_VERSION = 'YYYY.MM.DD'`，`CHANGELOG[0]` 的 `v` 填**同一个字符串**、`date` 填 `YYYY-MM-DD`。
- 同一天第二次发布起 → 手填子版本 `.2` / `.3`（如 `2026.10.12.2`），`v` 与 `APP_VERSION` 保持一致。
- 新条目放 `CHANGELOG` **数组最前面**；每次发布各记一条，**不做同日合并**，历史条目不回头改。
- `items` 是纯文本，渲染时 `esc`；**里面不能出现 `</script`**（build.js 全文件检查，注释也算）。

## 5. 完整流程（7 步）

```bash
# ① 定位：确认目标组现在是啥样
node tools/show_char.js 薇斯纳

# ② 改 src/data.js（唯一真源，不要碰根目录 index.html）

# ③ 语法自检（中文字符串极容易漏引号）
node --check src/data.js && node --check src/app.js

# ④ 回读验证：改动真的落进去了吗
node tools/show_char.js 薇斯纳

# ⑤ 数据自检
node tools/check_data.js

# ⑥ 构建（看输出是「校验通过」还是「版本日期待提交校验」的警告）
node build.js

# ⑦ 回归（动了角色卡配装条时）
node tools/check_card_labels.js --built
```

`tools/show_char.js` 的常用参数：

```bash
node tools/show_char.js 薇斯纳 梦见月瑞希   # 按角色名，打印全部配装组
node tools/show_char.js --set 血红之证       # 所有用到该套装的组
node tools/show_char.js --sub cd            # 追加属性含 cd 的组
node tools/show_char.js --manual            # 所有人工校准组（发版前扫一遍）
node tools/show_char.js --count             # 角色 / 配装组 / manual 组统计
```

## 7. 已踩过的坑

1. **只改 `subs` 不改 `equal`** —— 展示顺序变了，权重语义还是「同权」，方案页不跟着变。
2. **忘了把 `source` 改成 `manual`** —— 下次 `rebuild_data.py` 一跑，人工校准被重算规则整个覆盖，且不报错。
3. **忘了改 `APP_VERSION`** —— build 只 warn 不代劳，结果是警告常驻 + 更新公告不弹。
4. **写中文 JS 漏引号** —— 不跑 `node --check` 就会构建时才炸。写完必须 `node --check`。
5. **`optional` 写成裸词条 `['cr']` 丢了理由** —— 回填脚本历史上不认成对写法，理由会被清空。新写的一律用 `[[id, '理由']]`。
6. **改 `roles` 想改定位** —— 定位已改由套装派生，改 `roles` 无效（`AGENTS.md` §4.6）。
7. **`index.html` 直接编辑** —— 是构建产物，下次 build 覆盖。

## 8. 实例：2026-10-12 血红之证追加属性校准

需求：① 薇斯纳 · 血红之证，暴击伤害排到暴击率之前；② 梦见月瑞希 · 血红之证，追加属性增加暴击伤害，按「暴击率 ＝ 暴击伤害 ＞ 元素精通 ＞ 元素充能效率」排序。

```diff
 # 薇斯纳 [主推] 血红之证：cd 严格优先 → 删掉 equal、顺序前移、标 manual
-subs:['cr','cd','atkP','er'], subRules:{required:[], equal:[['cr','cd']], source:'heuristic'}
+subs:['cd','cr','atkP','er'], subRules:{required:[], equal:[], source:'manual'}

 # 梦见月瑞希 [备选1] 血红之证：补入 cd，cr = cd > em > er
-subs:['em','er','cr']
+subs:['cr','cd','em','er'], subRules:{required:[], equal:[['cr','cd']], source:'manual'}
```

同时 `APP_VERSION` / `CHANGELOG[0]` 由 `2026.10.10.3` 升为 `2026.10.12`，新增一条说明这两处人工校准的日志。回归：`check_data.js` 无异常、`build.js` 校验通过、`check_card_labels.js --built` 通过、追加属性排序回归 127/127 与角色卡一致。

**没有动**薇斯纳的备选组（饰金之梦）——需求没提，它仍是 `heuristic` + `cr=cd`。
