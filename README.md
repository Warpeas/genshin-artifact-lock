# 原神圣遗物锁定方案生成器

输入「每个角色的推荐套装 + 推荐主追加属性」，自动汇总出「每个圣遗物套装该锁什么、锁几件、给谁用」。

纯前端单文件应用，**不联网、不安装**，双击 `index.html` 即用。CSS/JS 全部内联，单个文件随便拷贝、发给别人都能打开。

> **在线地址**：https://warpeas.github.io/genshin-artifact-lock/

![角色配置](preview/01-角色配置.png)

## 一、项目目标

### 解决什么问题

背包里圣遗物越堆越多，但面对一件「绝缘套·充能沙」，你其实很难回答：

- 这个套装的沙漏，我该留充能沙还是攻击沙？
- 各留几件才够用？（养了 6 个角色，难道要留 6 件充能沙？）
- 哪些套装我根本用不上，可以整套喂掉？

### 核心思路

圣遗物锁定本质上是一个**三维汇总**：

```
套装 × 部位 × 主要属性  →  需不需要留、留几件、给谁用
```

每个角色贡献若干条需求（配装组 + 各部位可接受的主要属性 + 优先级），汇总引擎把所有启用角色的需求叠加进「套装 × 部位 × 主要属性」的格子里，一次性输出完整清单。

**产出物**：每个套装一组「游戏内锁定方案候选」（按追加属性需求聚类、数量不限），经你「并入 / 采纳」收敛后即可照搬进游戏；另有（可选展开的）逐套装详细件数清单——留什么、留几件、给谁用。

## 二、怎么用

### 路径 A：只想用，不改数据

1. 双击根目录的 **`index.html`**
2. **① 角色配置**：勾选你实际在养的角色
   - 懒得一个个点？用批量栏：一键全选 / 反选，或按**属性**（火水冰雷风岩草）、按**国度**（蒙德/璃月/稻妻/须弥/枫丹/纳塔/至冬/其他）、按**定位**（主C/副C/辅助）整类切换，三类可叠加
3. **② 锁定方案**：查看结果
   - 页面给出每个套装的**「游戏内锁定方案候选」**：候选数量不限，默认全部采纳，可用「并入…」合并、取消勾选弃用，收敛到游戏内每套 3 个预设以内再照抄
   - 想看「留几件、给谁用」的详细件数，勾选工具栏「显示详细件数」展开
   - 需要存档就点「复制游戏内方案」「复制清单」或「导出 CSV」（Excel 可直接打开）
4. **③ 追加属性规则**（可选）：拿不准某件胚子值不值得留，用评分器输入追加属性数值直接判定

> 你的勾选和编辑保存在浏览器本地（localStorage）。换设备或清缓存前，记得去 **④ 数据管理 → 导出 JSON** 备份。

### 路径 B：要改内置数据

两种方式，按需选择：

| 方式 | 适用场景 | 影响范围 | 要不要重新构建 |
|---|---|---|---|
| **界面里改**（推荐） | 校正个别角色的配装、加个新角色 | 只存在你自己浏览器里 | 不需要 |
| **改源码** | 批量修正角色库、新增套装、改权重模型 | 影响所有拿到 `index.html` 的人 | **需要**，跑 `node build.js` |

**界面里改**：点角色卡片打开浮窗，配装卡片上点「✎ 编辑」改套装、主要属性优先级、追加属性排序与 ★必选、国度与定位；改完点「保存」才生效，「数据管理」页可新增自定义套装。改坏了可用「还原这一组 / 还原为内置数据」退回内置原样，无需碰代码。

**改源码**：改 `src/data.js` 后执行：

```bash
node build.js
```

会重新生成根目录的 `index.html`。

> ⚠️ **根目录的 `index.html` 是构建产物，不要直接编辑它** —— 下次执行 `node build.js` 会被覆盖。所有修改都请改 `src/` 里的文件。

## 四、维护基础共用数据：改哪里

**绝大多数维护需求都集中在 `src/data.js` 一个文件里。**

| 想改什么 | 文件 | 位置（常量名） | 说明 |
|---|---|---|---|
| **内置套装清单 / 2 件套文案** | `src/data.js` | `SETS` | 格式 `{ name, bonus }`，`SET_NAMES` 和 `SET_BONUS` 由它自动派生，**不用手改**。日常增删改名也可在 **④ 数据管理 → 打开套装管理（浮窗）** 里做 |
| **改角色的配装、主要属性优先级** | `src/data.js` | `RAW_CHARS` | 见下方格式说明 |
| **改角色的国度 / 队伍定位** | `src/data.js` | `CH_META` | 格式 `'角色名': [国度, [定位...]]` |
| 主要属性可选范围（如新增某种杯） | `src/data.js` | `MAIN_STATS` | 按部位分组 |
| 追加属性种类 | `src/data.js` | `SUB_STATS` | — |
| 追加属性需求预设（双暴/精通流等） | `src/data.js` | `SUB_PRESETS` | **有序数组**，每项 `[词条id, 是否必选]`，越靠前越想要；名字见 `SUB_PRESET_NAMES` |
| 元素 / 国度 / 定位枚举 | `src/data.js` | `ELEMENTS` / `REGIONS` / `ROLES` | 新增国度或定位时改这里，批量栏按钮会自动生成 |
| 汇总权重、分级阈值、保留件数上限 | `src/app.js` | 文件顶部常量区 | 见「权重模型」一节 |
| 追加属性名次权重、追加属性池上限、聚类阈值 | `src/app.js` | `SUB_RANK_DECAY` / `SUB_CORE_TOP` / `SUB_POOL_TOP` / `SUB_POOL_MAX` / `MERGE_SIM_TH` | 见「追加属性排序模型」一节 |
| **更新公告 / 更新日志** | `src/data.js` | `APP_VERSION` / `CHANGELOG` | 改数据后把 `APP_VERSION` 改成当天日期（`YYYY.MM.DD`）并在 `CHANGELOG` **最前面**加一条 `{v, date, title, items}`；`CHANGELOG[0].v` 必须等于 `APP_VERSION`，否则公告不会弹或会重复弹 |
| 界面样式、配色 | `src/styles.css` | — | — |

### `RAW_CHARS` 角色库格式

```js
// [ 名称, 元素, 追加属性预设, builds, 沙, 杯, 冠 ]
['雷电将军', 'electro', 'er', [['绝缘之旗印']], ['er', 'atkP'], ['electro', 'atkP'], ['cr', 'cd']],
```

- **builds**：第 1 项是主推配装，其余为备选；单项含 1 个套装名 = 4 件套，含 2 个 = 2+2
- **主要属性数组**：按优先级从高到低排列，**第 1 项即最优解**
- 元素取值：`pyro` / `hydro` / `cryo` / `electro` / `anemo` / `geo` / `dendro`
- 追加属性预设：`crit`（双暴输出）、`critHp`、`critDef`、`em`（精通流）、`hp`、`def`、`er`（充能辅助）、`atk`、`heal`

改完后跑 `node build.js` 重新构建。构建脚本会做完整性校验（未知套装名、非法主要属性会报错），数据写错会当场拦下来。

## 五、权重模型

得分公式：

```
得分 = 配装优先级 × 件套形态 × 主要属性优先级   （跨角色累加）
```

| 维度 | 取值 | 权重 |
|---|---|---|
| 配装优先级 | 主推 / 备选 | 1.0 / 0.55 |
| 件套形态 | 4 件套 / 2+2 | 1.0 / 0.8 |
| 主要属性优先级 | 第 1 条最优；其后每条 `=` 同权 / `>` 降权 ×0.72 | 1.0 / 1.0 / 0.72 … |

### 分级阈值

| 得分 | 分级 | 含义 |
|---|---|---|
| ≥ 0.8 | **必留** | 有角色把它当最优解，至少留 1 件 |
| 0.4 – 0.8 | **过渡** | 只有次选或备选配装需要，有就用、不专门刷 |
| < 0.4 | 不显示 | 需求太弱，视为狗粮 |

### 建议保留件数

- **沙 / 杯 / 冠**：以该词条为**最优解**的角色数（同一角色多套配装不重复计数），区间 1–4
- **花 / 羽**：主要属性固定，件数 = 需要该套装的角色数，区间 1–4
- **暴击率冠与暴击伤害冠自动合并**为「二选一」——它们实际可互换，分开统计会严重高估（实测可把 12+3 件修正为 7 件）

以上常量在 `src/app.js` 顶部，可按需微调。游戏内方案的聚类 / 合并常量（`MERGE_SIM_TH`、`MAIN_MAX`、`MAIN_COVER`、`SLOT_STRICT`）也在同一区域，每个常量都有注释说明用途。

### 追加属性需求模型（= / > 重要度链）

追加属性不再用 0–1 数值权重，而是用**「排序 + 必选 + 重要度算子」**表达。界面上每条（首条除外）都有一个 `=` / `>` 开关，外加「上下移」和「☆/★」：

```js
// 一份追加属性需求 = 有序数组；req = ★必须；op 表示与上一条的重要度关系
//   op: '=' → 和上一条重要度一致（不衰减）；op: '>' → 比上一条更低（×0.72）
[{ id: 'cr', req: true, op: '>' }, { id: 'cd', req: true, op: '=' }, { id: 'atkP', op: '>' }, ...]
```

含义：**第 1 条最想要（权重 1.0）**，其后每条要么 `=` 与上一条同权、要么 `>` 降权。这样既保留了「越靠前越想要」的排序，又把「同重要 / 次重要」显式表达出来，而不是只靠隐含的位置序号。

> 旧存档里没有 `op` 字段的条目，统一按 `>` 处理，等价于改造前的 0.72^i 衰减，结果不变。

内部需要一个数值量（相似度比较、胚子评分、合并投票）时，按重要度链折算：

| 常量 | 默认值 | 含义 |
|---|---|---|
| `SUB_RANK_DECAY` | 0.72 | `>` 时权重 ×0.72；`=` 时沿用上一条权重；标了 ★ 再 ×1.25 |
| `SUB_CORE_TOP` | 3 | 前 3 名 ∪ 所有 ★ 视为「核心需求」，决定「包含任意 N 条」的基准 |
| `SUB_POOL_TOP` | 5 | 单个角色最多贡献 5 条追加属性 |
| `SUB_POOL_MAX` | 5 | 合并后追加属性池上限，再宽就等同于「不限」，失去筛选意义 |

**★必须**取的是「组内**全体**角色都标了必选」的交集（最多 2 个）——因为 ★ 在游戏内表示「没有就不锁」，只要有一个角色不需要它，设了就会漏锁该角色的件。

## 六、四个页面

### ① 角色配置

![角色配置](preview/01-角色配置.png)

- 内置 112 个可配装角色的常见配装（覆盖至 7.0 至冬版本），每个角色带「国度 + 队伍定位」标签；配装整理自社区常见推荐思路，6.6–7.0 新角色的配装可能随环境微调，建议在角色配置页按自己的练度再核一遍。剧情 NPC（如尼可、洛恩、雅珂达、莉奈娅等）无社区配装共识，故未纳入；套装名均对照米游社/米哈游百科核验，不含编造条目
- 每个角色卡片有攻略来源时显示 🔗 角标（点开角色即可查看）；链接统一在**角色编辑浮窗**的「攻略来源」区管理——每行一条，**点左侧 ↗ 直接打开链接**、可改、可删，底部「+ 添加链接」可增多个来源。链接取自**米游社角色攻略频道**（[https://baike.mihoyo.com/ys/strategy/channel/map/37/39](https://baike.mihoyo.com/ys/strategy/channel/map/37/39)）等真实攻略来源（不限定平台，亦可用 Game8 / KQM / B站 等），按「养成 / 配装 / 一图流 / 解析」为每个角色挑选最相关的 1–3 篇攻略（如 `miyoushe.com/ys/article/xxxxxx`），均真实可访问、不重复；找不到合适攻略的角色留空。工具对来源**不作任何解析**，仅存档你认可的配装攻略；你也可以换成自己信得过的链接。所有内置配装均对照米游社核验、不含编造条目
- 批量选择：全选 / 全不选 / 反选（作用于当前筛选结果）；按属性、国度、定位整类切换，点一次全选、再点一次取消，可自由叠加
- 搜索框支持角色名、套装名、国度、定位混合搜索
- 点卡片打开**角色编辑浮窗**（居中显示），上段改角色信息（名称 / 元素 / 国度 / 定位 / 备注 / 攻略来源），下段是**配装卡片列表**
- **配装卡片**：每张一眼看全「套装名（2+2 显示 `A + B`）+ 三部位主要属性 + 追加属性（★ 表示必选）」，按钮有「✎ 编辑 / 设为主推 / 还原这一组 / 删除」
- **配装编辑是第二层浮窗**（盖在角色浮窗之上）：改套装双下拉、主推、**主要属性（`=` / `>` 重要度 + 排序）**、**追加属性（`=` / `>` 重要度 + ★必选）**；**点「保存」才生效**，点取消 / 关闭 / 浮窗外会提示「有未保存的修改」再放弃。草稿机制保证中途乱点不会污染正在编辑的角色
- **套用下拉**（在配装浮窗里）：可整组复制**其他配装组**、套用**出厂预置**、或只用 9 种**追加属性预设**覆盖追加属性
- **新增配装组**：可选「空白（双暴默认词条）」或「复制配装 N」，新增后立刻打开编辑浮窗（不会留下空套装组）；此时点取消会把这组撤回，不留痕迹
- **删掉的预置能找回来**：角色编辑浮窗里「＋ 从预置添加」会列出**出厂里存在、当前没用上**的配装组，选中即加回
- **改坏了能还原**（三层粒度）
  - **只改主推**：配装区上方出现「↩ 还原主推」——只把「谁主推、谁备选」改回内置，不碰任何词条内容
  - **单组**：配装卡片上「整组还原」——套装 + 词条 + 主推一起回到内置原样
  - **整角色**：编辑浮窗左下角「还原内置」——名字 / 元素 / 国度 / 定位 / 备注 / 来源 / 全部配装一次性还原（启用状态保留）
  - 判定锚点是出厂指纹 `bkey`（`角色名#序号`）+ 出厂名 `skey`，**改名后照样能还原**；老存档加载时会自动补写 `bkey`
  - 配装卡片与角色卡片上的**「已修改」徽标**提示这一项已经和内置数据不一样了
  - **只改主推不算内容改动**：不会让「整组还原」按钮冒出来（主推单独归「还原主推」管）
- **添加属性一律走选择浮窗**：点「+ 添加主要属性 / + 添加追加属性」弹出第三层浮窗，**只列出还没添加过的属性**，点一个即加入；已添加的项可在行内下拉里直接换成别的（改成重复项会被拦截）
- **内置数据随版本自动更新**：每个配装组记着一个同步锚点 `fcanon`
  - 你**没动过**的组 → 内容自动跟着仓库里的新内置数据走
  - 你**自己改过**的组 → 一律保留不动（卡片标「已修改」），想用新版就点一次还原
  - 后台给角色**新增**的配装组不会自动塞进来（避免打乱你已排好的组合），可在「＋ 从预置添加」里按需选回

### ② 锁定方案

![锁定方案](preview/02-锁定方案.png)

页面主体是每个套装的**「游戏内锁定方案候选」**——先列出全部候选，由你收敛到能放进游戏的组合：

- **候选卡片**：按角色的**追加属性需求**自动聚类生成，**没有数量上限**；每个方案的**五个部位共用同一份追加属性条件**（写在卡片上方的条件条里），下面用紧凑行列出各部位主要属性
- **方案归属**：卡片标题注明「供谁使用」，同一套装的多个方案在游戏内共同生效（彼此是「或」的关系）
- **采纳 / 并入… / 拆回**：候选默认全部「已采纳」；「并入…」下拉把任意两个候选并成一套（可链式多并），「拆回」一键还原；取消勾选即弃用该候选。采纳数超过游戏内上限（每套 3 个）时，页面顶部出现橙色提醒——**是否压缩到 3 套由你决定**
- **全自动合并，没有滑块**：合并完全由「追加属性需求像不像」自动决定（追加属性余弦相似度 ≥ 0.88 才合并，阈值为固定常量）。主 C / 副 C 都要双暴 + 攻击 → 自然并为一套；辅助要充能 / 生命 / 精通 → 自动被拆开。界面不再提供「方案贴合度」这类需要自己调的参数
- **🧩 散件 / 过渡 保留规则**：页面顶部可开关与具体角色无关的保留条件（如稀有的元素伤害杯）。每条启用的规则会生成一份**候选方案**，与角色聚类结果**同权**参与「并入 / 采纳」，不再单独占用槽位；规则卡片以绿色左边框和「🧩 散件 / 过渡保留」标题区分。内置 4 条（元素伤害杯 / 双暴头 / 充能沙 / 精通杯，默认启用元素伤害杯）——**内置规则也能改**：点「编辑」可改名称 / 说明 / 部位 / 主要属性 / ★必须 / 追加属性，改动存进覆盖层并标「已修改」，「恢复默认」一键还原；自定义规则同样支持编辑与删除
- 单方案可单独复制；「复制游戏内方案」一键复制全部套装（只含已采纳的方案，超套会标注 ⚠️）
- 勾选「显示详细件数」可展开每套的建议保留件数与需求来源（必留 / 过渡 / 可喂）
- 元素伤害杯自动打「稀有·建议多留」标记；支持复制清单、导出 CSV、打印 / 存 PDF

#### 游戏内锁定方案 · 生成规则

对齐游戏内「背包 → 圣遗物 → 锁定功能 → 套装锁定方案」的实际规则：

| 规则 | 说明 |
|---|---|
| 预设数量 | 每种套装**至多 3 个自定义方案**（官方上限），多个方案在锁定时共同生效 |
| 可设部位 | 时之沙 / 空之杯 / 理之冠可分别设主要属性与追加属性；生之花 / 死之羽主要属性固定，只能设追加属性 |
| ★必须 | 勾选带 ★ 的追加属性，表示必须命中 |
| 命中条数 | 固定「**至少两条**」——圣遗物最终 4 条追加属性，至少 2 条落在追加属性池里才锁定（★计入总数） |
| 3 词条圣遗物 | 仅有 3 条追加属性时，所需数量自动减 1 |
| 主追加属性互斥 | 追加属性不可能与同部位主要属性相同。方案级统一追加属性后，仅自动剔除与花 / 羽固定主要属性（生命值 / 攻击力）冲突的项；沙 / 杯 / 冠的主要属性随方案而变，无法逐部位剔除——照抄时请自行留意（例如方案主要属性选了充能，则追加属性池里的充能效率对该部位是无效勾选，跳过即可） |

**固定算法（按角色的追加属性需求聚类，结果可复现）**

攻略明确指出——**需求差异大的角色不宜并入同一方案，否则会「存伪」**（把别的角色用不上的圣遗物也锁进来）。工具不再替你压到 3 套，而是给出**全部候选 + 手动整理**：

1. **角色分组**：**只看追加属性需求**——对使用该套装的角色取追加属性权重向量（名次衰减加权）的余弦相似度，做凝聚聚类：每一步合并「当前最相似的两组」，只有相似度 **≥ 0.88** 才真的合并，否则停手、保留为独立候选。
   主要属性**不参与相似度**，而是【逐部位独立合并】——因为「合并是按追加属性要求类似，单独每个部位合并主要属性要求」。
   阈值 0.88 是实测标定值：双暴输出 vs 攻击流 ≈ 0.93（合并 ✅），双暴输出 vs 双暴 + 生命流 ≈ 0.83（拆开 ✅），输出 vs 治疗辅助很低（拆开 ✅）
2. **候选合成**：每组角色生成一份候选方案——**全方案唯一一份追加属性条件**（★必须 = 组内全员必选的交集，最多 2 个；追加属性池 = 组内任一角色前 5 条需求，最多 5 条；命中条数固定「至少两条」），主要属性逐部位按「票数 × 重要度」降序取到累计覆盖 ≥ 70%，上限 3 个
3. **散件 / 过渡规则同权加入**：每条启用的保留规则转成一份候选（主要属性稀有条件 + 追加属性条件，命中条数同样固定为「至少两条」），与角色聚类候选一起参与后续整理
4. **手动整理**：用「并入…」把候选并成一套（★必须取交集、追加属性池取并集；合并后主要属性按逐部位重算并统一截断到 3 个，避免越并越宽），用「采纳」勾选决定最终要照抄的方案；超过每套 3 个时页面顶部提醒
5. **导出**：「复制游戏内方案」只导出已采纳的方案，格式与页面一致（每个方案先写五部位统一的追加属性，再逐部位列主要属性）

效果示例：绝缘套下香菱 / 行秋 / 雷电将军（攻击流）合并为方案一，夜兰（生命流）自动拆为方案二——两者追加属性需求不同，混在一起会互相污染。

### ④ 数据管理

![套装管理浮窗](preview/07-套装管理.png)

数据管理页含「套装管理」入口，点 **打开套装管理** 弹出浮窗，套装列表的改动立即影响所有下拉与方案页：

- **增删**：浮窗底部输入名称 + 2 件套效果即可添加自定义套装；内置套装点「隐藏」只是不显示（角色配装里的引用保留），随时可「恢复」；自定义套装点「删除」会真正移除并同步清掉角色配装里的引用
- **改名**：改完自动同步到所有角色的配装引用，会提示更新了多少处
- **改效果**：2 件套说明文案直接编辑
- **排序**：↑ / ↓ 上下移，顺序就是各处下拉与方案页的展示顺序
- **备份 / 恢复**：配置导出 / 导入 JSON（换设备、备份用）；清空启用状态、恢复内置默认库
- **更新日志**：卡片顶部显示当前版本号，下面按新→旧列出每次更新改了什么（内置角色 / 圣遗物都会随游戏版本手工维护）。大版本更新后首次打开会自动弹一次**更新公告**，读过就不再弹；「查看更新公告」可随时重看（手动查看不会清掉已读标记，不会导致重复弹窗）

> 旧存档（角色级 `subs` 数值权重 + `customSets`）会在加载时**自动迁移**：数值权重按大小降序转成排序（≥0.9 视为必选），`customSets` 合并进统一的 `state.sets`，不需要手动处理。

## 七、注意事项

- 内置配装整理自社区常见推荐思路，**随版本更迭请自行校正**；个别角色定位见仁见智（如某角色算副C还是辅助），点开卡片就能改
- 数据保存在浏览器 localStorage，**清除浏览器数据会丢失**，重要配置请先导出 JSON
- 部署到 GitHub Pages 时需注意：localStorage 按**域名**隔离而非路径，同一域名下放两份本工具会互相覆盖数据

## 附：部署与更新

### 首次部署（GitHub Pages）

1. 新建仓库，把 `index.html`（+ 可选的 `README.md`、`.nojekyll`）上传
2. 仓库 **Settings → Pages → Build and deployment**，Source 选 `Deploy from a branch`，分支选你的默认分支（**`main` 或 `master`，以仓库实际为准**）、目录 `/ (root)`
3. 等 1–2 分钟构建完成，访问 `https://用户名.github.io/仓库名/`

只上传 `index.html` 一个文件即可正常运行，页面内不含任何外部依赖。

### 后续更新

改完 `src/` 下的文件后重新构建，再把 `index.html` 上传覆盖即可：

```bash
vim src/data.js      # 1. 改数据
node build.js        # 2. 重新生成单文件版 index.html
# 3. 把 index.html 上传覆盖仓库里的同名文件，Pages 约 1 分钟后自动更新
```
