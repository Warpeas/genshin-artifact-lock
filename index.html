关于数据

  • 内置 0 个角色、0 个套装，整理自社区常见推荐，随版本变动请自行校正。
  • 「主推 / 备选」权重：主推 = 1.0，备选 = 0.5；主要属性优先级 1/2/3 权重 = 1.0 / 0.5 / 0.25。
  • 建议保留件数 = 以该主要属性为最优解的角色数（同一角色多套配装不重复计数），区间 1–4。
  • 2+2 配装对单套的件数需求更低，汇总时按 0.6 系数折算。
  • 主要属性 / 追加属性需求按配装组分别保存：同一角色换套装时可以有不同的词条需求。

使用说明

三步走

  1. ① 角色配置：勾选你实际要养的角色。点卡片可改套装、主要属性优先级和追加属性排序；主要属性 / 追加属性都越靠前优先级越高，追加属性还能点 ☆ 标成 ★必须。 一个角色可以有多组配装（4件套 / 2+2），每组的词条需求分开保存；新增配装组时会默认复制当前组的词条，也可以从别组一键复制。
  2. ② 锁定方案：每个套装给出「游戏内锁定方案候选」——按角色的追加属性需求自动聚类，每个方案的 五个部位共用同一份追加属性条件，主要属性逐部位列出，照着填进游戏即可。 没有槽位上限：候选可以有很多，用「并入…」手动合并、取消勾选「采纳」挑掉不要的，收敛到游戏内每套至多 3 个预设再照抄。 页面顶部还有「🧩 散件 / 过渡 保留规则」：与角色无关、只因主要属性稀有（如元素伤害杯）就值得留的圣遗物， 可单独开关；启用后每条规则会生成一份候选方案，与角色聚类结果同权参与合并与采纳。
  3. ③ 追加属性规则：给出分档判定 + 胚子评分器，解决「主要属性对了但追加属性能不能留」。
  4. ④ 数据管理 → 套装管理（浮窗）：点「打开套装管理」增删套装、改 2 件套说明、上下移排序；内置套装只是「隐藏」，可随时恢复。

怎么看方案

  • 方案 N：由追加属性需求相近的角色合并而来，标题写明「供谁使用」。同一套装的多个方案在锁定界面共同生效（彼此是「或」的关系）。
  • 采纳 / 并入… / 拆回：每个候选默认「已采纳」；「并入…」把两个候选并成一套，「拆回」还原。改动会保存； 采纳数超过游戏内上限（每套 3 个）时，页面顶部会给出橙色提醒。
  • 自动合并：方案按角色的追加属性需求相似度自动聚类——需求差不多（如主C / 副C 都要双暴 + 攻击）就并为一套， 差得多（辅助要充能 / 生命 / 精通）就分开；主要属性则逐部位独立合并。无需手动调参。
  • ★必须：金色词条，这件圣遗物必须有它，否则不锁定。来自组内全体角色都勾选了「必选」的追加属性（在角色抽屉里点 ☆ 设置），最多 2 个。
  • 至少两条：命中条数固定为「至少两条」——圣遗物最终 4 条追加属性，至少 2 条落在追加属性池里才锁定， ★必须的词条也计入这两条。契合得越多越好，不足两条直接喂掉。
  • 勾选工具栏「显示详细件数」可展开每套的建议保留件数与需求来源；不勾选时页面只显示可直接照搬的锁定方案。

注意

  • 花和羽毛主要属性固定，游戏内只能设追加属性，因此这两个部位对追加属性要求最严；方案级统一追加属性后，★必须 / 追加属性池只剔除与花 / 羽冲突的词条。
  • 空之杯的元素伤杯掉率极低，建议启用「🧩 散件 / 过渡 保留规则」里的「元素伤害杯」单独留一套。
  • 追加属性不可能与同部位主要属性相同。方案级统一追加属性后，已自动剔除与花 / 羽固定主要属性（生命值 / 攻击力）冲突的项；沙 / 杯 / 冠的主要属性随方案而变，无法逐部位剔除——照抄时请自行留意，跳过即可。
  • 数据存在本机浏览器，换设备用「数据管理 → 导出 JSON」迁移。
