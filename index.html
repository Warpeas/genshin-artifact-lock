  • 「主推 / 备选」权重：主推 = 1.0，备选 = 0.5；主要属性优先级 1/2/3 权重 = 1.0 / 0.5 / 0.25。
  • 建议保留件数 = 以该主要属性为最优解的角色数（同一角色多套配装不重复计数），区间 1–4。

使用说明

三步走

  1. ① 角色配置：顶部可按元素 / 国度 / 定位筛选（三者可叠加，还能配合搜索框与「只看已启用」）， 有筛选时右上角显示「筛出 N / 总数」；旁边「↓ 正序 / ↑ 倒序」可把整个列表反过来（会记住你的选择）。 勾选你实际要养的角色。点卡片打开编辑浮窗：上面是角色基本信息，下面是配装卡片—— 每张卡片一眼看全套装、三部位主要属性、追加属性，点卡片上的「✎ 编辑」会再弹出一个配装编辑浮窗。 词条改完点「保存」才生效；点取消 / 关闭 / 浮窗外，会提示「有未保存的修改」再放弃。 一个角色可以有多组配装（4件套 / 2+2），每组的词条需求分开保存；新增时可以选「空白」或复制现有组， 删掉的内置预置组还能从「＋ 从预置添加」里选回来。
  2. 改错了怎么办：配装卡片与角色卡片上都可能出现「已修改」徽标——说明这一项已经和内置数据不一样了。 单组改坏 → 卡片上「整组还原」（套装 + 词条 + 主推一起回到内置原样）； 只是把谁设成主推搞乱了 → 配装区上方会多出「↩ 还原主推」（只动主推，不碰词条）； 整个角色改乱 → 编辑浮窗左下角「还原内置」（名字 / 元素 / 国度 / 定位 / 备注 / 来源 / 全部配装一次性还原）。 删掉的内置配装组可以在「＋ 从预置添加」里选回来。
  3. 内置数据会随版本更新：你没动过的配装组会自动跟着仓库里的新数据走； 你自己改过的组一律保留不动（卡片上标「已修改」），想用新版就再点一次还原。
  4. ② 锁定方案：每个套装给出「游戏内锁定方案候选」——按角色的追加属性需求自动聚类，每个方案的 五个部位共用同一份追加属性条件，主要属性逐部位列出，照着填进游戏即可。 没有槽位上限：候选可以有很多，用「并入…」手动合并、取消勾选「采纳」挑掉不要的，收敛到游戏内每套至多 3 个预设再照抄。 页面顶部还有「🧩 散件 / 过渡 保留规则」：与角色无关、只因主要属性稀有（如元素伤害杯）就值得留的圣遗物， 可单独开关；启用后每条规则会生成一份候选方案，与角色聚类结果同权参与合并与采纳。
  5. 旅行者按元素形态拆成 6 个独立条目（旅行者·风 / 岩 / 雷 / 草 / 水 / 火）：各形态元素不同、配装不同，可分别启用、分别编辑。 同理，国度已细分出挪德卡莱（与至冬分开）；若你的存档是旧版，打开时会自动把角色的国度 / 定位纠正一次，之后你自己改的不再覆盖。
  6. 列表排序：① 角色卡、② 方案页的套装块、③ 底部的「各套装推荐追加属性」表格，旁边都有 「↓ 正序 / ↑ 倒序」按钮——点一下换方向，选择会记在本机。 套装列表（②③）还多一个「图鉴 / 推荐」两档切换： 图鉴＝套装库顺序（排序顺序来自米游社图鉴），稳定、不会因为你勾了谁就跳来跳去； 推荐＝用的人多的排前面，会随你勾选的角色变化。角色列表则按国度排列（蒙德 → 璃月 → … → 其他·旅行者）。
  7. ③ 追加属性规则：给出分档判定 + 胚子评分器，解决「主要属性对了但追加属性能不能留」。
  8. ④ 数据管理 → 套装管理（浮窗）：点「打开套装管理」增删套装、改 2 件套说明、上下移排序；内置套装只是「隐藏」，可随时恢复。
  9. ④ 数据管理 → 更新日志：内置角色 / 圣遗物会随游戏版本手工维护，这里记录每次更新改了什么。 大版本更新后首次打开会自动弹一次更新公告（读过了就不再弹）；想再看就点「查看更新公告」。

怎么看方案

  • 方案 N：由追加属性需求相近的角色合并而来，标题写明「供谁使用」。同一套装的多个方案在锁定界面共同生效（彼此是「或」的关系）。
  • 采纳 / 并入… / 拆回：每个候选默认「已采纳」；「并入…」把两个候选并成一套，「拆回」还原。改动会保存； 采纳数超过游戏内上限（每套 3 个）时，页面顶部会给出橙色提醒。
  • 自动合并：方案按角色的重要属性（第 1 条起同等重要的那一截 + ★必选，通常就是双暴）自动聚类—— 重要属性撞上就并为一套；次要属性（攻击力% / 生命值% 之类）不同不影响合并，会按角色分组上色显示，实际给谁再按手上的圣遗物定。 主要属性则逐部位独立合并。无需手动调参。
  • ★必须：金色词条，这件圣遗物必须有它，否则不锁定。来自组内全体角色都勾选了「必选」的追加属性（在角色抽屉里点 ☆ 设置），最多 2 个。
  • 至少两条：命中条数预设「至少两条」——圣遗物最终 4 条追加属性，至少 2 条落在追加属性池里才锁定， ★必须的词条也计入这两条。需要更严就在该方案的卡片上把下拉改到 3 / 4 条（也可放松到 1 条），每个方案单独记。
  • 收起：点「🧩 散件 / 过渡 保留规则」标题左侧的箭头可把整块收成一行标题——只是不再显示，已启用的规则照常生成候选方案。
  • 勾选工具栏「显示详细件数」可展开每套的建议保留件数与需求来源；不勾选时页面只显示可直接照搬的锁定方案。

注意

  • 花和羽毛主要属性固定，游戏内只能设追加属性，因此这两个部位对追加属性要求最严；方案级统一追加属性后，★必须 / 追加属性池只剔除与花 / 羽冲突的词条。
  • 空之杯的元素伤杯掉率极低，建议启用「🧩 散件 / 过渡 保留规则」里的「元素伤害杯」单独留一套。
  • 追加属性不可能与同部位主要属性相同。方案级统一追加属性后，已自动剔除与花 / 羽固定主要属性（生命值 / 攻击力）冲突的项；沙 / 杯 / 冠的主要属性随方案而变，无法逐部位剔除——照抄时请自行留意，跳过即可。
  • 数据存在本机浏览器，换设备用「数据管理 → 导出 JSON」迁移。

中英文切换

  • 顶栏右上角有一个语言下拉，一次把界面文案和数据名一起切过去：选 English 后按钮、说明、以及角色名 / 套装名 / 属性名全都变英文，选择会记住。
  • 切成 English 后显示官方英文本地化名（如 胡桃 → Hu Tao、逐影猎人 → Marechaussee Hunter），属性、国度、定位、部位同样跟随。
  • 搜索框两种语言都认：不管当前显示哪种，输入「胡桃」或「Hu Tao」、「逐影猎人」或「Marechaussee」都能搜到。
  • 复制 / 导出的文本始终保持中文——游戏内的锁定界面是中文，照抄时才对得上。
  • 「更新日志」里记录的是历史改动，保留原始中文不翻译。
  • 进阶：底层仍保留分别设置界面语言与数据语言的能力（setLang('ui', …) / setLang('data', …)），供接口或脚本单独调用；界面上不再拆成两个开关。
